# Contributing

Thanks for helping make **Awesome Obsidian Bases** the best resource for the Bases
ecosystem.

## Adding an entry

1. Fork the repo and create a branch: `add/<project-name>`.
2. Add exactly **one entry** per pull request.
3. Put it in the most relevant section, alphabetically where practical.
4. Use this format:

   ```markdown
   - [project-name](https://github.com/owner/project-name) — one-sentence description.
   ```

5. Open a PR using the template.

## What belongs here

An entry must:

- be **usable today** (a working release or a clone-and-run repo),
- be **related to Obsidian Bases** — a view, plugin, starter vault, template, agent
  skill, MCP server, converter, or guide that touches Bases,
- have a **README** that explains what it does and how to run it,
- have a valid, public link.

## What does not belong here

- Abandoned or unmaintained experiments (no commits for 12+ months, no response to issues).
- Paid-only tools with no free tier or trial.
- Link-farming, referral links, or self-promotion without substance.
- Anything unrelated to Bases.

## Quality bar

- Prefer primary sources (the project's own repo or docs).
- One sentence, factually accurate, no marketing adjectives ("revolutionary", "blazing").
- No star counts — they go stale and invite arguments.

## Review

Maintainers may ask for changes, move an entry to a better section, or decline an
entry that does not meet the bar. Be kind — see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Reporting issues

Use the issue templates for a broken link, a correction, or a new-section proposal.
